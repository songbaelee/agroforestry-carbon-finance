Module 2A

Carbon generation forecasts

The Y-axis is normalized. A value of 100 represents the highest relative biomass accumulation shown here, not exact tons or credits.

Why do biological assumptions change the carbon curve so much?

This view compares simplified biological growth patterns across agroforestry archetypes. The curves are normalized for educational purposes rather than tied to exact hectares, tons, or verified credits. The core intuition is simple: trees grow slowly, and timing matters.

Solid lines show the 100% baseline. Dotted lines show the water-adjusted scenario.

Module 2A lesson

Carbon forecasts are biological forecasts first.

Before a project can sell carbon credits, it needs trees to survive, grow, and accumulate carbon over time.

The same project size can produce very different carbon curves depending on water availability, growth speed, survival, and system type.

Semi-arid systems are generally more sensitive to water stress than humid tropical systems.

Module 2B

Carbon generated vs. verified

This view uses the shade-grown perennial archetype from Module 2A to isolate one timing lesson: generated carbon is not automatically verified carbon.

When does biological carbon become verified carbon?

The solid blue line shows carbon generated by the biological growth curve. The dashed blue line shows the same carbon after a simplified verification delay. The gap between the two lines is the timing problem Module 2B is meant to teach.

Module 2B lesson

Carbon can exist before it is verified.

Trees may already be storing carbon, but the project usually cannot rely on that value until it has been verified.

Module 2C

Verified carbon pricing and market uncertainty

This view uses verified carbon from Module 2B and translates it into three possible revenue outcomes.

Why might a project accept a lower contracted price instead of waiting for the spot market?

All three lines use the same verified carbon quantity. The contracted path may be lower but more predictable. The spot-market paths show that waiting can create upside, but also downside.

Module 2C lesson

Verified carbon still has price risk.

Contracted sales can make future revenue easier to plan, even if the price is lower.

Spot markets may produce higher revenue later, but the project carries the risk that prices are weaker when credits are ready to sell.

Module 3A

Cost categories

This view breaks project costs into categories and shows how rollout pacing changes when those costs occur.

How do project costs change when rollout speed changes?

Rapid rollout concentrates planting and engagement costs early. Balanced and phased rollouts spread those costs across more years while staffing, maintenance, and MRV continue over time.

Module 3A lesson

Costs are operating commitments.

A carbon project has to organize planting, support farmers, maintain trees, measure results, and manage the program. Rollout speed changes when those costs hit.

A project may eventually recover its costs but still fail to attract commercial investors if returns are too low relative to risk and duration.

About this tool

This project began as an attempt to explain agroforestry carbon finance in a simpler and more visual way. Carbon finance models can become extremely complicated very quickly, especially when discussing biological growth, verification timing, financing structures, and revenue sharing.

The early modules intentionally keep the model simple by focusing first on carbon price, project length, timing, and basic costs. Later modules add simplified financing, grant support, and farmer revenue sharing mechanics.

The goal is educational rather than predictive. This is not a full project finance model and should not be used for investment decisions.

The tool was built iteratively using ChatGPT, Chart.js, and GitHub Pages.

For users interested in the underlying mechanics, a simplified Excel workbook is available with the core cash-flow assumptions, IRR logic, grant support adjustments, and farmer-share sensitivity.

How this tool is different

Most existing tools focus either on carbon accounting or detailed financial modeling. This project is intentionally simpler. It is designed as an intuition-first learning tool to help users understand how biology, timing, revenue, financing, and benefit sharing interact in agroforestry carbon projects.
